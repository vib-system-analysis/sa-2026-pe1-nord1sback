# 3. Заинтересованные стороны

| Заинтересованная сторона | Интерес / цель | Ожидания | Возможные риски или конфликты |
|---|---|---|---|
| Владелец гардероба (основной пользователь) | Вести каталог и быстрее подбирать одежду | Удобный ввод, точные записи, полезные рекомендации | Ошибки распознавания, лишние действия, утечка фотографий |
| Разработчик / команда проекта | Создать поддерживаемую систему | Ясная граница, проверяемые требования, ограниченный объём | Разрастание функциональности, неопределённые интеграции |
| Владелец продукта | Получить полезный продукт в заданных ограничениях | Понятная ценность, приемлемая стоимость и качество | Низкая вовлечённость, расходы на AI API |
| Поставщик AI | Обработать запрос и вернуть результат | Валидный формат запроса, соблюдение лимитов | Изменение API, стоимость, задержки, недоступность |
| Поставщик инфраструктуры хранения | Надёжно хранить данные | Корректные запросы и управление доступом | Сбой, потеря данных, ограничения тарифа |
| Специалист по безопасности/приватности | Снизить риски обработки личных изображений | Минимизация данных, согласие, контроль доступа и удаление | Передача данных без достаточного основания |
| Поддержка/администратор (если роль предусмотрена) | Разбирать инциденты | Диагностируемые ошибки и ограниченные полномочия | Необоснованный доступ к личным данным |

## Приоритет

Основной пользователь — ключевая заинтересованная сторона. Его способность исправлять результаты распознавания и управлять собственным каталогом является обязательным принципом проектной границы. Остальные роли и внешние системы требуют уточнения в соответствии с реальной реализацией.
