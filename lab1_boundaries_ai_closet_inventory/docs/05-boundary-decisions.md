# 5. Обоснование границ и журнал решений

## 5.1. Ключевые решения

### D-01. Пользователь остаётся владельцем окончательного решения о данных каталога

**Решение:** AI может предлагать атрибуты вещи, но подтверждение и исправление доступны пользователю.

**Обоснование:** ошибка в категории или цвете ухудшает поиск и рекомендации. Возможность ручной коррекции снижает последствия ошибок распознавания.

**Последствие:** интерфейс должен различать предложенные и подтверждённые значения либо обеспечивать простой процесс проверки.

### D-02. Рекомендации ограничены доступным каталогом

**Решение:** минимальная версия рекомендует комплекты из вещей, записанных в каталоге.

**Обоснование:** это делает результат проверяемым и снижает риск предложить вещь, которой у пользователя нет.

**Последствие:** качество рекомендаций зависит от полноты каталога. Система должна корректно сообщать, если данных недостаточно.

### D-03. Необязательные интеграции не включаются в обязательную границу

**Решение:** погода, календарь, магазины и социальные сети не считаются частью минимальной версии без подтверждённых требований.

**Обоснование:** каждая интеграция добавляет стоимость, вопросы приватности, отказные сценарии и обслуживание.

**Последствие:** такие функции можно добавить отдельным решением после подтверждения ценности.

### D-04. Внешний AI-провайдер показан как условная зависимость

**Решение:** контекстная модель показывает AI-провайдера, но не фиксирует конкретного поставщика.

**Обоснование:** источник проекта не подтверждает используемый стек в доступном описании лабораторного задания.

**Последствие:** перед реализацией необходимо выбрать между внешним API и локальной моделью, оценив качество, стоимость, задержку и приватность.

### D-05. Обработка фотографий входит в пользовательский процесс, но доступ к галерее не подразумевается автоматически

**Решение:** пользователь явно выбирает или загружает фотографию; автоматическое сканирование всей галереи исключено из текущей границы.

**Обоснование:** минимизация доступа уменьшает риск неожиданной обработки личных изображений.

**Последствие:** любые более широкие разрешения требуют отдельного обоснования и согласия.

## 5.2. Журнал решений

| ID | Решение | Статус | Основание / следующий шаг |
|---|---|---|---|
| D-01 | Пользователь может проверить и исправить AI-атрибуты | Рабочее решение | Подтвердить требованиями интерфейса |
| D-02 | Рекомендации используют вещи из каталога | Рабочее решение | Уточнить правила комплектования |
| D-03 | Необязательные интеграции исключены из минимальной границы | Принято для черновой границы | Пересмотреть при появлении требований |
| D-04 | Конкретный AI-провайдер не выбран | Открыто | Сравнить качество, цену, задержку и приватность |
| D-05 | Нет неявного доступа ко всей фотогалерее | Принято для черновой границы | Проверить UX и платформенные ограничения |

## 5.3. Критерии пересмотра границы

Границу следует пересмотреть, если:
- появится подтверждённое требование на интеграцию с погодой или календарём;
- пользовательский сценарий потребует совместного гардероба;
- выбранная AI-модель потребует иной схемы обработки изображений;
- появятся измеримые данные, что ручной каталог обеспечивает достаточную ценность без AI;
- требования безопасности или стоимость провайдера сделают текущий подход неприемлемым.
